### 🟠 M1 (medium) — 강제 `Phaser.WEBGL` + Phaser가 tick 구동 → WebGL 부재 시 게임 전체 정지

- **위치**: `src/game/bootstrap.ts:101` `type: Phaser.WEBGL`
- **논리 증거**: 논리 tick은 `GameScene.update → application.advance(delta)`
  (`src/game/game-scene.ts:24-26`)로만 구동된다. WebGL 초기화 실패 시 `new Phaser.Game`가
  `setTimeout` 콜백(`bootstrap.ts:132`) 안에서 실패 → Scene update 루프 부재 → `advance`
  미호출 → 뱀이 전혀 움직이지 않는다. DOM 쉘(메뉴/Start/READY)은 렌더되므로 사용자에게는
  "READY에서 멈춘 앱"으로 **조용히 실패**한다. 화면만 없는 것이 아니라 게임 자체가 정지.
  Snake는 rect/line Graphics만 그려 Canvas 2D 렌더러로 동일 동작한다.
- **선례**: `docs/coordination/handoffs/SG-002.md` line 105 — *"`type: Phaser.WEBGL` 강제는
  스파이크 목적상 의도적이나 테스트의 `renderer:"WEBGL"` 단언과 순환적이다. 제품(SG-005)에서
  `Phaser.AUTO` 폴백 여부 재검토 권고."* 명시적으로 제기됐으나 제품에 미반영. 강제 WEBGL과
  단언이 순환적이라 Canvas 폴백 경로는 한 번도 검증된 적 없음.
- **사용자 영향**: 대상("지원 OS·최신 브라우저")에선 저확률이나, WebGL 차단(블록리스트 GPU,
  강화 프라이버시 설정, 일부 VM/headless) 시 재현당 영향은 치명적(플레이 불가).
- **근거**: AC-U08(필수 게임 그래픽 렌더), AGENTS §6 "화면 효과 실패는 게임 진행을 중단시키지
  않는다"의 정신.
- **최소 수정**: `Phaser.WEBGL` → `Phaser.AUTO` (식별자 1개, WebGL 실패 시 Canvas 폴백).
  비용·위험 무시 가능 → **SG-022 반영 강력 권고**.

### 🟡 L1 (low) — 이중 키보드 리스너: `app.ts` document keydown이 production에서 항상 억제되는 dead path

- **위치**: `src/ui/app.ts:136-149` 대 `src/game/input-controller.ts:70-103`
- **증거**: bootstrap이 InputController를 항상 장착한다. (a) board 포커스 키는
  `onBoardKeydown`의 `stopPropagation()`으로 document에 도달하지 못하고, (b) board 밖
  shell-shortcut 키는 `onDocumentCapture`의 `stopImmediatePropagation()`로 제거된다. 결국
  `app.ts`의 document 리스너가 dispatch에 도달하는 경로가 없다. 두 경로가 phase 계산도 다르다
  (app.ts=마지막 렌더 `previousPhase`, InputController=live `application.snapshot.phase`).
  UI 단위테스트(InputController 부재 환경)에서만 살아 있어 유지된다.
- **영향**: 사용자 무영향. 유지보수 함정 — `onDocumentCapture` 제거 시 조용히 이중 dispatch가
  부활해 AC-U06("버튼 한 번 활성화 = command 한 개")을 위반한다.
- **근거**: AC-U06 / 리뷰 우선순위 "과잉 범위·복잡도".
- **최소 수정**: 외부 input controller가 키보드를 소유할 때 쉘이 자체 document 리스너를
  건너뛰도록 flag를 전달, 또는 두 지점에 억제 계약을 명시 주석화.
